文案、分镜和成片。素材是在 Rhino 8 里重新逐帧录制的 1080×1920 满屏画面，不是裁出来的横屏录屏。

  • 结构开场 3 秒就演招牌功能：打砖块多球混战，按老板键一帧变成幕墙立面。第 6 秒交代「一半拓扑优化，一半摸鱼」，然后三个游戏各走一遍「高光 → 一帧变图纸」，再「摸够了，干正事」转到 2D / 3D 拓扑优化，最后是 AI 开发、安装和片尾。
  • 素材写了一个在 Rhino 里运行的录制工具：接管游戏的时钟，每帧推进 1/60 秒并截图。机器人在玩，高光（多球、双层消除、连击 ×5、升级）按剪辑需要准时发生，老板键是游戏真实的一帧切换。拓扑优化每一帧都是真实的某一步迭代。
  • 文案三个方向各写一稿，由「短视频剪辑」和「建筑师观众」两个视角打分，取反转稿的主线、高光稿的开场。评审挑出的事实问题都改了：3-2-1 是真实 3 秒不加速，拓扑优化标出倍速，用时写明「1.0.0 版」。
  • 第四版换成更退后的配乐 Kevin MacLeod《Pamgaea》（你从三首试听里选的），响度降到 −19.5 LUFS，剪切点按它的 94 BPM 重新对拍；去掉说教味的句子，改成调侃的口吻（片尾改成「祝摸鱼愉快 / 老板路过？按 ` 就好」）；另做一版英文：字幕全部英文，游戏和实机画面用英文界面重录。

整片节奏

横轴是秒，每格是一小节（四拍，约 2.55 秒）。颜色是镜头的作用：老板键切换（深色）在整片里均匀出现四次。每条字幕至少停 2.5 秒，多数 3–5 秒，够看清。

老板键：切换前一帧 → 切换那一帧

四个游戏的切换都是游戏自己的一帧切换，剪辑没有加任何转场。伪装图原本按横屏构图，录制时在切换的同一帧把相机按竖屏重新取景（只动相机，不改画的内容）。

分镜

每镜一张成片截图。「画面」是镜头里实际发生的事，「为什么」是这样安排的理由，「坑」是录制或剪辑时遇到的问题和处理办法。

文案是怎么选出来的

三个方向各写一稿：反转（同事在画幕墙？其实在打砖块）、高光快剪、AI 一句话故事。两位评审各自打分（1–10 分）。

两位评审都把反转稿排第一（结构最好：每个游戏都是「玩 → 一帧 → 图纸」），但都认为高光稿的开场最强（第一帧就是多球混战，第 2 秒切立面）。故事稿最老实，但老板键到 29 秒才出现，「AI 写的」也不是观众装插件的理由。

成片取反转稿的主线、高光稿的开场和片名定义句「一半拓扑优化 · 一半摸鱼」、故事稿的「方块能自己建模」「Examples 电池」。四宫格「同时伪装」被评审否掉（四段素材对齐冒充同时，不真实），改成雨燕段里一个小标签「Alt+Tab 切走，也会自动伪装」。

怎么做出来的

游戏和求解器本来按真实时间跑、画在屏幕大小的视口里。离线逐帧录制让每一帧都完整渲染、时间完全可控。

字幕统一放在画面 67–78% 的高度、左对齐：上面是游戏自己的分数 HUD；抖音、小红书会在最下面约 20% 叠加标题和简介，右边约 12% 是点赞、评论按钮。

配乐 Kevin MacLeod《Pamgaea》，CC BY 4.0，片尾和简介都署了名。整曲正好 94 BPM；取第 38–63 小节：开头 6 小节没有低音，正好用来渐入，结尾是曲子自己的收尾。

需要你决定

  • 要不要配人声？现在是字幕 + 配乐。每镜都写好了口播句（在 docs/intro-video-storyboard.md），可以用你自己的声音录一遍再混进去。
  • 标题用哪个？备选：①同事在认真画幕墙？其实他在 Rhino 里打砖块 ②给 Rhino 装了个老板键：一帧从小游戏变回图纸 ③一个 Grasshopper 插件：一半拓扑优化，一半摸鱼。封面字「老板一来，变图纸」。
  • 要不要上传？中文版发抖音、小红书；英文版可以发海外平台（如 YouTube Shorts、Instagram Reels）。可以先准备好标题、简介、话题和封面（小红书封面用 3:4），发布按钮留给你点。
  • 安装那两镜要不要重录？Package Manager 和 Examples 菜单用的是 11-08 的旧录屏，清晰度比其他镜头低。可以在 Rhino 里按竖屏重录。
